# Outcome

将 `dsh-passwords-ext` 改造成适合内网小团队使用的受限入口：本机 DSH 上游继续只在 `127.0.0.1:3080` 提供完整管理能力，内网用户统一通过可配置的 `3088` 网关登录；网关显示当前账号并提供退出入口，为每个子用户分配且只暴露一个工作区根目录，并在网关入口隐藏、阻止 DSH 全局设置修改。

# Scope

- 在网关页面提供常驻账户入口，显示当前用户名、角色、分配工作区和权限摘要，并提供退出登录；账号被删除或封禁时主动提示并结束当前登录。
- 将原本位于 DSH 设置卡片中的账号、工作区、配额、沙盒和网络管理迁移到独立的网关账户中心；Admin 可管理子用户、账号备注和 `banned` 状态，子用户只能管理自己的密码并查看自己的限制。
- 子用户工作区支持两种互斥分配方式：按用户名自动创建，或由 Admin 指定一个目录；每个子用户始终只有一个工作区根目录。
- 按用户名模式在可配置用户工作区根目录下创建 `<username>` 目录，自动注册为 DSH Workspace，并保存为该用户唯一允许目录。
- 指定模式由 Admin 从可用目录/已注册 Workspace 中选择一个目录；不得多选或留空。
- 在网关可观察的 DSH HTTP/WebSocket 表面过滤工作区、会话和目录内容，并拒绝区域外创建、分叉、浏览、读取、写入、上传和 Git 操作。
- `3088` 网关按角色控制 DSH 原生设置：Admin 保留完整设置入口与写入能力；子用户隐藏设置入口，仅允许页面启动和选择已有模型所需的只读数据，并拒绝全局设置、模型 Provider、凭据、插件和全局权限写入。
- Admin 可在网关账户中心配置网关监听模式（仅本机、局域网、指定地址）和端口；DSH 上游地址保持只读 loopback，配置应用失败时回滚。
- 保持现有 SQLite 用户、会话、权限和用量数据可用，并为旧子用户建立安全的单根目录分配语义。

# Non-goals

- 不修改 DeepSeek Harness 核心源码。
- 不提供操作系统、容器、虚拟机或独立 DSH 进程级硬隔离。
- 不支持一个子用户绑定多个工作区根目录。
- 不在删除用户时删除其目录或文件。
- 不回滚或自动取消删除账号前已经由 DSH 接受并开始运行的任务。
- 不在用户名变更时自动移动现有目录和文件。
- 不提供每用户独立模型凭据、插件集合或 DSH_HOME。
- 不在本 change 中完成公网 HTTPS、域名、证书或多实例编排。
- 不发布 npm 包或变更上游官方仓库。

# Acceptance examples

- A1：通过网关登录后，侧边栏常驻显示当前用户名和角色；点击账户入口可查看权限摘要并退出，退出后返回登录页且旧 Cookie 不再放行。
- A2：Admin 通过网关入口访问时，DSH 原生设置按钮保持可见且完整设置可用；子用户通过网关访问时设置按钮不可见，直接进入设置页面或调用设置写接口被拒绝；本机 `127.0.0.1:3080` 访问保持原行为。
- A3：网关 Admin 可以添加、删除或修改模型 Provider、API Key、插件和全局 Permission；网关子用户只能读取页面初始化所需的主题、语言和已有模型列表并选择已有模型，不能执行这些全局设置写入。
- A4：Admin 可在账户中心创建子用户并选择“按用户名”或“指定目录”；未选择分配方式、指定模式未选目录或试图选择多个目录时不能保存。
- A5：按用户名创建 `alice` 时，系统在配置根目录下创建 `alice` 目录、注册 DSH Workspace，并将该规范化目录保存为 Alice 唯一允许区域。
- A6：指定目录模式保存后，该规范化目录成为用户唯一允许区域；目录不存在、不可访问或无法规范化时保存失败且原权限不变。
- A7：子用户登录后，工作区列表、会话列表和目录浏览只显示其根目录及子目录；Admin 仍可查看全部工作区和会话。
- A8：区域外绝对路径、`..` 穿越、编码后的穿越路径和通过符号链接逃逸均被 Host/网关拒绝，返回明确的 `403`，且不执行目标操作。
- A9：子用户不能在区域外创建或分叉会话、读取或写入文件、上传文件或执行 Git 下载；未知的高风险写入入口对受限用户默认拒绝。
- A10：Admin 可把网关配置为仅本机、局域网或指定监听地址，并修改网关端口；DSH 上游保持 loopback 且不可在页面中改成对外监听，失败应用自动恢复上一份可用配置。
- A11：旧子用户若已有一个合法允许目录，则保留为“指定目录”；没有合法单目录分配的旧用户必须先完成分配才可进入工作区，不再把空列表解释为允许全部。
- A12：删除用户不会删除其工作区文件；用户名变更默认保留原工作区路径并在 UI 中明确提示。
- A13：在当前 Node/DSH 环境完成构建、自动化测试和本地双入口验证：`3080` 仅 loopback，网关入口执行账户、目录和设置限制。
- A14：Admin 删除或封禁子账号后，该账号的所有后续 HTTP 操作立即被拒绝，活跃 WebSocket/SSE 被关闭，已打开页面显示“账号已被删除或已停用，当前登录已失效”并跳转登录页；Admin 收到成功提示。已经开始运行的 DSH 任务不回滚，但该账号不能继续查看或控制。
- A15：主账号不能通过网关删除、封禁或降级自己，系统始终保留一个有效主账号；主账号改名或改密码后，全部旧登录和长连接立即失效，所有页面提示“管理员凭据已变更，请重新登录”并跳转登录页。
- A16：Admin 可为每个子账号维护可选备注并切换现有 `banned` 状态；备注仅 Admin 可见。`banned = true` 后该账号立即不能登录或继续操作，全部旧认证和长连接失效并收到停用提示；恢复为 `false` 后只能通过新登录恢复。主账号不能被标记为 `banned`。

# Constraints and invariants

- `3080` 是本机管理入口；对外/内网入口只能是网关。
- 网关限制必须由注入的受限入口标记判断，不能把安全行为仅硬编码到端口号 `3088`。
- UI 隐藏不是安全边界；所有敏感写入必须在网关/Host 再次校验。
- 路径授权使用规范化与真实路径边界，必须处理符号链接和不存在目标的父目录校验，不能仅使用字符串前缀。
- Admin 账号不受工作区过滤，并可通过网关或本机上游修改 DSH 全局模型、凭据和插件设置；子用户在网关入口不得看到或调用这些写入能力。
- 子用户只允许一个根目录；空目录授权不得代表“全部允许”。
- 配置写入、目录创建、Workspace 注册和权限保存需要避免部分成功；失败时不得留下越权或未登记状态。
- 每个网关请求都必须重新确认账号仍存在且有效；删除、封禁、改名或改密必须主动关闭按用户追踪的长连接，不能只等待 JWT 到期。
- 系统必须始终保留一个有效主账号；主账号不能从网关自删、标记为 `banned` 或自降级。
- `banned` 是唯一的可逆停用真值，不新增 `enabled` 或其他并行状态字段。
- 当前变更提供网关层逻辑隔离，不宣称抵御本机用户直连上游、未受控 MCP 或宿主进程攻破。

# Decisions

- 使用一个紧耦合的 Native change，不拆分 Supervisor children；账户 UI、工作区分配、网关策略和网络配置共享同一客户端、Host 和数据库边界。
- 网关入口按角色控制 DSH 设置：Admin 保留完整设置，子用户隐藏设置并禁止写入；`3080` 本机入口保留原有完整设置。
- 通过网关的 Admin 可管理 `dsh-passwords-ext` 自身账号、工作区、配额、沙盒和网络配置，也可使用 DSH 原生设置管理模型、API Key、插件和全局设置；子用户不能进入这些设置。
- 工作区分配默认按用户名，也允许 Admin 指定一个目录；不支持多目录。
- 按用户名模式的根目录可配置，默认位于数据库目录旁的 `workspaces/` 下。
- 指定目录通过目录选择控件选择一个可验证目录；保存后自动注册或复用对应 DSH Workspace。
- 删除用户不删除数据；改名不自动移动数据；账号备注仅用于 Admin 管理且不向子用户公开；账号停用继续使用现有 `banned` 字段。
- 网关监听支持仅本机、局域网和指定地址；上游固定为 loopback，并提供失败回滚。
- HTTP 局域网模式允许用于当前受控体验，但 UI 必须显示未加密警告；HTTPS 不在本 change 范围。
