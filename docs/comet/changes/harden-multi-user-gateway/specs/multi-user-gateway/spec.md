# 多用户受限网关完整规格

## 目标与角色

系统在单个 DSH Host 前提供一个登录网关。角色分为主用户 Admin 和子用户。Admin 通过网关管理账号、网关配置以及 DSH 全局设置；子用户通过网关使用 Admin 已配置好的 DSH 能力。DSH 本机上游入口同样保留模型、凭据、插件和全局设置管理。

## 网络入口

- DSH 上游必须监听 loopback，默认 `127.0.0.1:3080`。
- 网关监听配置支持：仅本机 `127.0.0.1`、局域网 `0.0.0.0`、或一个经过验证的指定本机地址。
- 网关端口可由 Admin 配置；当前默认体验端口为 `3088`。
- 上游地址在网关管理页面只读，不能配置为非 loopback。
- 监听配置变更先验证并保存上一版本，再重启网关；新配置启动失败必须恢复上一版本。
- HTTP 局域网模式显示明文传输警告。

## 账户入口与会话

- 网关页面常驻显示当前用户名和角色。
- 账户菜单展示当前工作区、沙盒、上传/Git 开关和配额摘要。
- 账户菜单提供退出登录；退出必须清除网关认证 Cookie 并跳转登录页。
- Admin 账户菜单提供子用户、工作区分配、权限和网络配置管理。
- 子用户只能修改自己的密码，不能管理其他用户或网络设置。
- Admin 删除或封禁子用户时，网关立即使该用户的现有认证失效，关闭其活跃 WebSocket/SSE，并向已打开页面发送账号失效提示后跳转登录页。
- Admin 删除成功后看到明确反馈。已经由 DSH 接受并开始运行的任务不回滚或自动取消，但被删除用户不能继续查看、控制或发起操作。
- 主账号不能通过网关删除、封禁或降级自己，系统不能进入无有效主账号状态。
- 主账号修改用户名或密码时，全部旧认证与活跃长连接立即失效；发起变更的页面和其他设备均显示管理员凭据已变更提示并跳转登录页。
- 每个子账号具有可选管理备注，并继续使用现有 `banned` 作为账号停用状态。备注仅 Admin 可读写，不参与登录身份、目录路径或权限判断。
- 子账号默认 `banned = false`；Admin 设置 `banned = true` 后，网关立即拒绝其登录和后续请求、关闭活跃 WebSocket/SSE，并显示账号已停用提示。恢复为 `false` 不恢复旧会话，用户必须重新登录。
- 主账号不能被设置为 `banned = true`。

## 工作区分配

- 每个子用户必须且只能拥有一个授权根目录。
- 创建或编辑子用户时，Admin 选择“按用户名”或“指定目录”。
- 按用户名模式使用 `<configured-root>/<username>`，创建缺失目录，规范化真实路径，注册或复用 DSH Workspace，并保存为唯一授权根目录。
- 默认用户工作区根目录为数据库目录旁的 `workspaces/`，可由部署配置覆盖。
- 指定模式通过目录选择控件选择一个目录。目录必须存在、可访问且可规范化；系统注册或复用对应 Workspace 后保存为唯一授权根目录。
- 指定模式不能多选，任何模式都不能保存空授权。
- 旧用户恰有一个合法允许目录时迁移为指定模式；空目录、多个目录或非法目录状态需要 Admin 修复，修复前不能访问工作区。
- 用户改名不自动移动目录；删除用户不删除目录、Workspace 文件或会话日志。

## 工作区、会话和目录可见性

- Admin 的工作区和会话列表不受过滤。
- 子用户只接收授权根目录及其子目录对应的 Workspace、Session 和文件树条目。
- 区域外 Workspace、Session、搜索结果和目录条目不得先下发再由 UI 隐藏。
- 目录浏览根固定在授权根目录，不能导航到父目录。

## 路径授权与操作限制

- 所有路径在授权前进行 URL 解码、平台规范化和真实路径边界判断。
- 已存在目标以真实路径判断；新目标以最近存在父目录的真实路径判断。
- `..`、编码穿越、相似前缀目录和符号链接逃逸必须拒绝。
- 子用户区域外的新建/分叉会话、Workspace 变更、文件读取/写入/上传、Git 下载和高风险工具操作返回 `403`，且不得部分执行。
- 子用户不能将沙盒权限提升到高于 Admin 分配的级别。
- 对受限用户无法安全分类的新写入或执行入口默认拒绝；只读静态资源和页面初始化流量可放行。

## 设置与模型边界

- 网关页面按角色控制 DSH 原生设置入口：Admin 保持可见并拥有完整设置能力；子用户隐藏设置入口。
- Admin 通过网关可以管理模型 Provider、凭据、API Key、插件和全局 Permission。
- 子用户可以读取主题、语言、模型列表和页面初始化所需的非敏感设置，并在会话中选择 Admin 已配置的模型。
- 子用户调用设置写入、模型 Provider 增删改、凭据 set/unset、API Key 修改、插件安装/卸载/启停或全局 Permission 修改时，网关返回 `403`。
- 子用户直接进入设置页面或通过直链触发设置 UI 时，网关返回首页或明确的无权访问提示。
- `dsh-passwords-ext` 自身的账户与网关管理使用独立账户入口，不依赖子用户不可见的 DSH 原生设置页面。
- 网关为明文 HTTP 时，Admin 设置页面必须醒目提示模型凭据和会话数据传输未加密。

## 持久化与兼容

- 继续使用现有 SQLite 用户、认证、权限、用量和审计数据。
- 新增工作区分配模式、根目录和账号备注需支持幂等迁移，并保持合法单目录权限和现有 `user_permissions.banned` 状态不变；不新增第二套停用真值。
- 配置、目录、Workspace 和权限更新使用可恢复顺序；失败时恢复旧权限或记录明确待修复状态。
- 原版 dsh-passwords 数据库可在不重建账号的情况下升级使用。
- 认证校验不能只依赖 JWT 有效期；每个请求和新建实时连接都要确认账号仍存在、未封禁且凭据版本有效。网关维护按用户索引的活跃长连接，以支持删除和封禁时即时断开。

## 安全边界

该能力提供网关层工作区访问控制，不提供操作系统级租户隔离。它不保证防御本机用户直连 loopback 上游、第三方未受控进程/MCP 或 Host 进程攻破。完全不可信租户需要独立系统账号、容器或独立 DSH 实例。
