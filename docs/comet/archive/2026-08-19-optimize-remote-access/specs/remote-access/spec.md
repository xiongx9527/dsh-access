# 远程访问优化规格

## 隧道传输

- Cloudflare quick tunnel 继续指向本机 `127.0.0.1:<gateway-port>`，不指向 3080 或新增 3081。
- cloudflared 启动时使用 HTTP/2 协议选项，避免依赖 UDP QUIC 的网络环境无法建立数据面连接。
- 隧道状态继续区分空闲、下载、启动、运行、停止和错误；错误详情不得包含密钥、Cookie 或内部命令行秘密。

## cloudflared 获取与缓存

- PATH 中已有可执行文件时优先复用，并复制到 dsh-access 自己的受保护缓存目录。
- 缓存支持标准可执行文件名和对应平台发布资产名。
- 缓存不存在时按平台和架构选择资产，并按配置的下载源顺序尝试；源失败可回退到下一个源。
- 下载完成后验证文件存在、可执行和可启动；失败时清理临时文件，保留可重试状态。
- 下载过程不读取或返回访问管理账号密码、JWT、SETUP_KEY 或数据库密钥。

## 公网隧道自动恢复

- 只有用户从远程访问页面明确开启公网访问后，系统才记录自动恢复意图。
- dsh-access 启动时先启动并确认 3088 网关，再读取恢复意图并异步启动隧道。
- 自动恢复生成新的临时 URL；旧 URL、旧二维码和旧状态不得继续显示为运行中。
- 隧道恢复成功后刷新公网 URL、二维码、phase 和 startedAt。
- 用户手动关闭公网访问时删除恢复意图，后续重启不再自动拉起。
- 自动恢复失败只更新远程访问错误状态，不阻塞账号登录网关；用户可在页面重试。
- 自动恢复的隧道和手动启动的隧道使用完全相同的 3088 登录认证和 WebSocket/SSE 保护。

## 响应压缩

- 网关根据请求的 `Accept-Encoding` 选择 Brotli 或 gzip；不支持时原样流式转发。
- 只对大型 JSON 或 text 响应使用通用压缩，小响应不压缩。
- 已带 `Content-Encoding` 的响应、SSE、WebSocket、图片/音频/视频等二进制响应不走通用压缩。
- HTML 注入流程保持独立：先按既有流程解压、注入和重新编码，不重复经过通用压缩。
- workspace、session、目录和其他受权限影响的响应先完成解析、过滤、改写，再按客户端协商结果压缩。
- 改写响应时必须删除旧的 `Content-Length` 和 `Content-Encoding`，重新设置与实际响应体一致的头。
- 压缩失败时不得返回半截响应；应关闭响应或回退为安全的未压缩完整响应。
